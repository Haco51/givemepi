# PR-0028: Concurrent Storage Pipeline

## 목적

PR-0027에서 확정한 durable storage와 async lifecycle 위에 실제 성능 경로를
구현한다. PR-0029의 측정·분석 작업과 섞이지 않도록, 이 문서는 구현 범위와
구현 순서를 관리한다.

## 반드시 유지할 계약

- chunk identity와 canonical codec bytes 변경 금지
- NodeLifecycle durability 및 실패·복구 계약 유지
- Progress telemetry 호환성 유지
- synchronous fallback 유지
- sync/async P/Q/T 결과 동일성 유지
- memory budget 및 bounded queue 상한 유지

## 구현 순서 및 상태

### 1. StorageManager 동시성 경계 확정 — 완료

- index publication과 in-flight identity를 mutex로 보호
- file store/load는 index 보호 구간 밖에서 수행
- 중복 identity와 동시 store 충돌 방지

### 2. Async writer/reader 병렬 실행 — 완료

- manager-wide serialization 제거
- worker가 독립적으로 StorageManager store/load 수행
- bounded queue와 shutdown/failure 계약 유지

### 3. Spill 경로 data movement 개선 — 완료

- BinaryNode에서 Chunk로 변환한 뒤 async queue에 move 전달
- queue 진입 전 P/Q/T 불필요한 복사 제거
- move 전 stored size를 보존해 progress/accounting 정확성 유지

### 4. Compression backend 추가 — 완료

- `none`과 bounded LZ4 codec 지원
- ChunkStore durable store/reload/CRC round-trip 검증
- CI에 `liblz4-dev` dependency 고정
- compression 선택이 identity domain에 들어가지 않는지 확인

### 5. 플랫폼 적용 가능성 점검 — 완료(기본 튜닝 미적용)

- CPU: Intel Core Ultra 9 185H, online CPU 22개, 1 socket, 1 NUMA node
- NUMA node 0에 CPU 0~21과 약 31 GiB 메모리가 모두 배치됨
- explicit HugeTLB: `HugePages_Total=0`, `Hugetlb=0`
- Transparent Huge Pages: `always` 활성화, 별도 강제 설정은 하지 않음
- 현재 process affinity: CPU 0~21 전체 사용 가능
- `/tmp`: tmpfs이므로 현재 storage benchmark의 file I/O 결과는 실제 디스크
  장치 성능을 대표하지 않음

결정:

- NUMA placement는 단일 node 환경이라 PR-0028에서 적용할 대상이 없음
- HugeTLB는 설정 가능한 reserved page가 없어 적용하지 않음
- CPU affinity는 hybrid-core 성능 차이를 확인할 별도 workload가 없으므로
  기본 적용하지 않음
- THP 정책 변경은 시스템 전역 영향이 있으므로 코드나 benchmark에서 강제하지 않음
- 실제 NVMe/filesystem과 다중 NUMA 장비 검증은 PR-0029의 platform matrix로 이관

### 6. PR-0028 기능 검증 및 정리 — 진행 중

- 전체 CTest와 sync/async 결과 동일성 확인
- multi-chunk spill/reload benchmark baseline 기록
- LZ4 durable round-trip 및 실패 경로 확인
- 코드·CI·결정 문서 정리
- 변경사항을 PR-0028 단위로 분리한 뒤 commit/push

## PR-0028 완료 조건

- 위 1~4단계 구현이 모두 반영됨
- 전체 테스트 통과
- sync/async P/Q/T 결과와 lifecycle 상태 동일
- bounded queue와 memory budget 위반 없음
- PR-0029에서 수행할 측정·최적화 항목이 문서로 분리됨

## PR-0029로 넘기는 항목

- 100/512 MiB/1 GiB 전체 workload matrix
- cold/warm, 5회 반복, p50/p95 측정
- file read/write·CRC32C·codec·GMP decode·queue wait 계측
- buffer 재사용 및 streaming 최적화
- CRC/read/GMP 병목 최적화
- 대형 데이터와 ASan/UBSan 검증
- NUMA/Huge Pages/affinity의 실측 기반 적용 여부

  동일 P-bit 결과를 확인했다.

- 전체 workload와 단계별 병목 결과는 PR-0029 문서에서 관리한다.
